# DistribuTAK

開発用 ATAK-CIV 5.8.0.9 の S20 と Xperia 1 を、同じ Wi-Fi の LAN で試すプラグインです。管理者がグループを作り、招待 QR を画面に出します。もう一台はプラグインのカメラで読み、加入して証明書を受け取ります。「接続する」でセッションを結び、双方が「試験DATAを1回送る」を押して確認します。CoT の地図表示・同期・転送は行いません。

起動時に Noise の握手、暗号の転送、TOTP を自己確認します。単調時計は全経路で `SystemClock.elapsedRealtimeNanos`、TOTP と外来の印の期限（再起動をまたぐため）は端末の壁時計です。Bouncy Castle の軽量 API を使い、provider は登録しません。自己確認が失敗した場合は通信しません。

## LAN と画面

ツール一覧の「DistribuTAK」を開きます。Wi-Fi の Network が一つだけあり、有効な IPv4 があるときに操作できます。複数の IPv4 はネットワーク順のバイト列で先頭を選びます。ソケットは `Network.bindSocket` でその Wi-Fi に結んでから、選んだ IPv4 と保存した UDP ポートで開きます。IPv6・リンクローカル・モバイル回線・VPN は使いません。Wi-Fi にインターネット接続は不要です。

ポートは初回に 49152〜65535 から乱数で選んで保存します。変更するときは先に通信を止めます。Wi-Fi が切れた・番地が変わった場合も通信と招待を停止し、秘密の配列を消します。復帰後は手で「接続する」を押します。この段では相手一台を扱います。加入した直後は、管理者が握手に使う公開鍵と加入先のIPv4・ポートを、最初の握手を待つための情報として包んで保存します。最初の握手で相手を認証して証明書と番地を保存できたら、この情報を消します。握手前に停止やATAKの再起動があっても、「接続する」でこの情報から待ち受けを再開できます。相手の IP やポートが変わったときの発見は未実装です。DHT、NAT の穴あけ、自動再接続は後の段で扱います。

招待 QR は URL の文字列・コピー・共有を提供せず、60 秒、閉じる、画面が隠れる、アプリが背景へ移る、加入成功、Wi-Fi の切断で消します。QR の画面とカメラの画面には `FLAG_SECURE` を付けます。画面写しの防止は実機での確認が必要です。Wi-Fiの通知では、Network・選んだIPv4・使えるWi-Fiの数の変化をその場で記録します。一度選べなくなって同じ回線へ戻っても、古い結果を使いません。同じ状態の通知だけなら、読み取りを続けられます。隠れたり背景へ移ったりしたあとに届いたQRやカメラの結果は捨て、押し直すまで画面を開き直しません。Wi-FiのNetworkまたはIPv4が変わった場合も、口が開いていない段から読み取りと権限待ちを取り消します。QR が消えても招待の登録は残り、1 回の使用、24 時間、ATAK の再起動、招待の再表示で失効します。同時に作れる招待は一つです。

「招待を読む」を押したときだけ、ホストの Activity の公開 API でカメラの許可を求めます。許可したあと画面が開かなければ、もう一度押してください。拒否されたときは許可が必要な旨を表示します。Camera2 の YUV の Y 平面だけを解析し、画像・QR・URL をファイルへ保存しません。読めた、閉じた、隠れた、一時停止、Wi-Fi の切断、60 秒、終了で読み取りを止めます。SDK の見本のコードは使っていません。

QRとカメラの枠は、表示中のウィンドウの短辺の85%をdpで決めます。縦向きでは説明とボタンを下、横向きでは横へ置きます。QRのビットマップはmutableで作り、表示から外して画素を消してからrecycleします。後始末中のRuntimeExceptionはホストへ渡さず、残りの消去・解放を続けます。画面の表示・ボタン・カメラの開始・権限の復帰・遅延処理は共通の実行口でRuntimeExceptionを捕まえ、秘密の画面を片付けて通信を止めます。固定の失敗通知を一度試し、その表示も失敗したときは再通知しません。Errorは捕まえません。

QRは誤り訂正M、余白4モジュールです。画像は表示幅に合わせ、最大1024画素とし、拡大時は最近傍で境界をぼかしません。この段で読める最長のIPv4招待（190文字）の固定例は、QRの版10・57モジュールでした。生成と読み取りの固定1000例も確認しています。

カメラはYUVとSurfaceTextureの共通サイズから1280×720を優先し、1920×1080を上限にします。同じバッファ寸法で縦横比をそろえ、TextureViewが行うセンサー方向の回転を考慮したうえで、画面の回転とcenter cropの行列を適用します。枠の大きさと画面の回転が変われば行列を更新します。向きの式は[Androidの公開の説明](https://developer.android.com/media/camera/camera2/camera-preview)によります。SDKの見本のコードは写していません。

自動焦点は機器が対応するCONTINUOUS_VIDEOを優先し、なければ対応するCONTINUOUS_PICTUREを使います。どちらもなければテンプレートの設定を使います。解析は最新の画像だけを受け取り、Y平面のpixelStrideが1なら行ごとに写します。通常のQR検出で失敗した場合の4方向の試行は維持し、一時配列を使い終わりに消します。端末での焦点・向き・解析時間は実機で確認します。

## 鍵と所属の保存・消去

ホストの application Context の `getNoBackupFilesDir()/distributak/` に保存します。`/sdcard/atak` は使いません。ATAK の UID の内部領域であり、ATAK の中のほかのコードからは隔てられません。

AndroidKeyStore の取り出せない AES-256-GCM 鍵（別名 `io.github.hidemas_suzuki_aka_ziek.distributak.wrap.v1`）で、身元・握手・グループ・管理者の鍵と所属記録を包みます。StrongBox は求めず、利用者認証は不要です。ハードウェアによる保護は保証しません。provider が作る 12 バイト IV と 128 ビットタグを使い、外枠は `DTKS` 版 1、用途とヘッダを AAD とします。保存の上限は 1 MiB、更新は `AtomicFile` です。外枠の `DTKS` は版1のままで、中に包む所属記録は版2です。実機の保存はまだないため、旧形式の版1は受け付けません。加入結果は暗号化した `joining.bin` に仮に保存し、核の加入の成功を確認してから `state.bin` に原子的に確定します。中断・期限切れ・世代の変更なら仮保存を消し、起動時に残っていた仮保存も使いません。包みのポートを正とし、途中停止で公開設定と食い違ったときは認証済みの値で公開設定を直します。

招待・TOTP・URL・セッション鍵・cookie は保存しません。ATAK を再起動して所属を復元したあとも、通信の開始は「接続する」で行います。Keystore の鍵の消失、改ざん、未知の版、壊れた記録は固定の文で停止し、自動で鍵やグループを作り直しません。

「消去」は確認のあと、消去途中の印を残し、通信を止め、Keystore の別名、包みと一時ファイル、公開設定、相手の記録を消し、メモリの秘密の配列を 0 で埋めます。途中で落ちた場合は起動時に消去を最後まで行います。壊れた設定や包みを読む必要はありません。消去後は秘密を持たない完了印を残し、別のグループを作るか、新しい招待を読めます。所属済み、または消去途中のときは作成できません。消去時に旧ポートの設定を削除し、49152〜65535から独立に引き直して保存します。偶然同じ番号になっても使います。新規作成ではグループID・管理者鍵・PSK・端末の身元鍵・握手鍵を新しく生成します。TOTPの秘密は招待QRを出すたびに新しく生成し、保存しません。新規作成や加入が成功して包みを保存したあと、完了印を消します。新規作成と加入の確定では、途中印を残してから保存を確定し、消去済みの完了印を消して、最後に途中印を消します。初めての保存は `initial.pending`、消去後の保存は `erase.pending` で区別します。途中印が残っているときは、起動時に作りかけの包み・加入の仮保存・設定・Keystoreの保存鍵を削除します。消去したことがなければ未所属へ、消去後なら消去済みへ戻ります。両方の途中印が残ったときは消去済みを優先します。復旧の読み書きが失敗したときは、途中印を残して操作を止めます。

Java の秘密の配列は使い終わりに 0 で埋めます。String、Bitmap、JCA と OS の中の写しの完全な消去は保証できません。フラッシュの上書き消去も保証しません。削除する Keystore の別名はこのプラグイン専用です。

Wi-Fiがない、通信中、所属済みなど操作の前提が合わないときは、固定の文を出して状態を保ちます。保存・暗号・検査の失敗では操作を止めます。加入に失敗した場合は管理者側の状態も確認します。管理者が招待を出せる場合は、新しい招待でやり直せます。管理者が返事を出したあとで加入側が確定前に失敗すると、管理者側にだけ登録が残り、新しい招待を出せないことがあります。

この場合、加入しようとした端末で別のグループを作ります。もとの管理者側は消去してから、新しい管理者の招待を読んで加入します。両方の端末が消去済みでも、どちらかが別のグループを作り、もう片方が加入すれば2台で戻せます。旧グループの招待やメンバーの記録は、新しいグループでは使えません。確認できていないメンバーを取り消して招待し直す機能は、後の段で扱います。

## 組み立てる

JDK 17 と Android SDK（platform 36）を用意し、このディレクトリの `local.properties` に次を設定します。このファイルは Git の追跡から除外しています。SDK の例のコードは使いません。

```properties
sdk.dir=/absolute/path/to/Android/Sdk
distributak.sdk.jar=/absolute/path/to/main.jar
distributak.takdev.jar=/absolute/path/to/atak-gradle-takdev.jar
```

minSdk は 23 です。ATAK 5.8.0.9 の公開資料では値が見つからなかったため、利用者の決定により、端末の OS が持つパッケージ情報で確かめた値を使います（ADR 0030 答え132）。`java.time` など API 23 にない Java の API は core library desugaring（desugar_jdk_libs 2.1.5）で使えるようにしています。

```sh
./build.sh
./build.sh testCivDebugUnitTest
./build.sh lintCivDebug -x takdevLint
./lint-core.sh
../core/build.sh clean test
```

`JAVA_HOME` の既定は `$HOME/miniconda3/envs/atakdev` です。核の Gradle wrapper を使います。Gradle のキャッシュはリポジトリ直下の `out/distributak/`、プラグインの出力は `out/distributak/plugin/` に置きます。APK は `out/distributak/plugin/build/outputs/apk/civ/debug/distributak-plugin-civ-debug.apk` です。Protocol Buffers は核のビルド設定（protobuf-javalite / protoc 3.25.5、Gradle plugin 0.9.4）を使います。release のビルドは無効です。

上の lint のコマンドは Android lint の解析とレポートを実行します。debug でも難読化を要求する takdev の追加検査だけを外します。debug の難読化は無効のままです。

通常の `lintCivDebug` は核を外部の依存として扱い、核のソースを解析しません。核は `./lint-core.sh` で確かめます。このスクリプトは Protocol Buffers のソースを生成し、核の全ソースと生成ソースを minSdk 23・desugar_jdk_libs 2.1.5 で直接解析します。NewApi があれば失敗します。一時の Android library と結果は `out/distributak/core-api-lint/` に置きます。Android SDK の場所は `ANDROID_HOME`（未指定なら `ANDROID_SDK_ROOT`、どちらもなければ `$HOME/Android/Sdk`）で指定できます。

## CoT の同期と同意（制約）

根拠は ADR 0030 の答え 166・168・171〜173、`docs/02-functional-spec.md` 6.2、`04-detailed-design.md` 7 章です。グループに入る前に、次の点を利用者が理解して同意することを前提にします。

**送る物**: セッションが確立している間、自分の位置を同じグループの相手へ送ります。自分の ATAK で作った物は、作り方を確かめた種類（送る種類の表）だけを送ります。今の版では表が空なので、作った物は送りません。DistribuTAK の外から ATAK が受けた物、見分けのつかない物、DistribuTAK を起動する前から地図にある物は送りません。

**受けた物**: 受けた CoT を ATAK の地図に入れます（取り込みは有効）。柵の実機の確かめ（受入の条件 #11 の (i)(ii)）は 2026-11-13 に利用者の 2 台で通りました。受けた物は `getInternalDispatcher()` だけで入れ、`PreSendProcessor2` の柵で、受けた uid の CoT を ATAK の送り出しから止めます。柵が登録されていないとき、柵に無い uid、外から先に ATAK に入った物と同じ uid（外来の印）、世代の合わない物は入れません（答え 169 (2)）。外来の印は、DistribuTAK から同じ uid が来ない限り残します。最後にほかの経路から見えたあと、DistribuTAK から同じ uid を初めて保存できた時から 10 分たつと印を消し、そのとき保存している最新の版を取り込みます（答え 176。続けて届いても延ばさない。途中でほかの経路から見えたら数えるのをやめる）。印が消えたあとは、ほかの経路から同じ uid が見えても印は付き直らず、後勝ちになります。数え始めた時刻は端末の壁時計で保存し、再起動をまたぎます。端末の時計を戻すとその分だけ待ちが長くなり、進めると早く終わります。取り込みの直前の解析か `isValid` で入力が無効と分かった 1 件は、通信を止めずに見送って数えます（答え 175）。ほかの失敗は今までどおり止めます。自分の位置の取り込みは、2026-11-13 に利用者の 2 台で両方向に通りました（#11 前半）。

**止められない経路**: 受けた物を ATAK に入れたあと、次の経路で外へ出ることを、このプラグインは止められません。

- ATAK の自動の送り直し、編集のあとの送り出し、手での共有と書き出し、削除の放送
- ATAK の起動からプラグインが柵を戻すまでの間
- ほかのプラグインとの `PreSendProcessor2` の登録の取り合い
- 停止・消去・取り外しのあとに地図に残る物
- 利用者が設定した TAK サーバー。ATAK の中の部品やほかのプラグインが `CommsMapComponent.sendCoTToServersOnly` を直接呼ぶと、柵を通らずにそのまま TAK サーバーへ出ます（利用者の 2 台で確かめました。どの部品がこの道を使うかは確かめていません）。TAK サーバーにつながっている間に取り込みを止める仕組みは作りません（答え 171 (2)）
- プラグインの無い受け手、画面のキャプチャ

グループの相手の物を、グループの外の TAK サーバーや端末へ出したくないときは、TAK サーバーの接続とほかのプラグインを外してから使ってください。

## 実機で確かめる担当と証拠

実機へのインストール・起動・タップは claude と利用者が行います。作業者は `adb` を使いません。対象は利用者自身の S20 と Xperia 1 の開発版だけです。詳細なタップの手順は `out/reviews/20261112-distributak-lan/worker-report.md` に記載します。

状態と数は画面と logcat のタグ `DistribuTAK` に出します。画面にはグループへの参加と相手の登録の状態を表示し、グループ・自分・相手の識別値は短くした値も表示しません。送信の印は `LAN_TEST_TX count=<件数>`、受信は `LAN_TEST_RX count=<件数>` で、ログにも識別値を含めません。DATA は固定の `DT-LAN-TEST` と版 1 のバイトだけで、押したときに 1 通送ります。受けた中身はログに出さず、返事・再送・他の相手への転送もしません。自分の送信数だけでは受信の証拠にならないため、相手の受信数と合わせて確かめます。

招待 URL・鍵・TOTP・PSK・中身は logcat、Intent、コマンド引数へ渡しません。QR とカメラを画面写しや録画の対象にしないでください。証拠は QR を閉じたあとの状態画面と固定のログだけにします。APK、ログ、画面写しを外へ公開しません。

## 配布について

組み立てた APK は配布・アップロードせず、S20 と Xperia 1 での確認だけに使います。輸出の扱いは未確認です。TPP（tak.gov/user_builds）は使えることを確認済みで、TPC（TAK Product Center）の認証は将来の作業です。release の署名は扱いません。暗号をアマチュア無線の電波区間へ出しません。
