# 作業者の手順

最初に `AGENTS.md` と `CLAUDE.md` を全部読む。`CLAUDE.md` の「ガードレール」はすべてに優先する。

## 1. 始める

1. 起動の指示にある「目標」を **`/goal` の目標として設定する**（create_goal ツール）。目標の文は指示のとおりにし、勝手に広げたり狭めたりしない。
2. 目標のファイル（`out/agents/goals/...`）があれば読む。根拠として示されたドキュメントの節を読む。タスク ID（`DTAK-N`）があれば `backlog task view <ID> --plain` でタスクも読む（状態は変えない）。
3. 作業の前に、分からないところを洗い出す。仕様・値・手順・試験の合格の条件のうち、ドキュメントで決まっていないものは
   **推測せず**、まとめて1通で `claude` に問い合わせる:
   ```
   tools/agents/ask.sh <自分の名前> claude <本文のファイル>
   ```
   本文には「分からないこと」「読んだファイルと節」「考えられる選択肢（あれば）」を書く。返事が来るまで、その点に依存する作業はしない。
   時間切れ（終了コード 2）なら、もう一度 `tools/agents/wait-msg.sh <自分の名前>` で待つ。

## 2. 作る

- 作業する場所は、起動したときの場所（オーケストレーターが用意したワークツリー）だけ。その外のファイルは変えない。
- まわりのコードの書き方（名前の付け方・コメントの量・言い回し）に合わせる。識別子は英語、ドキュメントは日本語。コードのコメントは日本語と英語の両方（日本語が先、英語があと。規則は `CLAUDE.md` 作業ルール）。
- 試験を先に書き、失敗するのを確かめてから実装する。既存の試験・lint を壊さない。
- 新しい暗号方式を足さない。HPKE の info/aad と署名の接頭辞を変えない。ATAK の SDK のコード・javadoc・AP40 の文章を書き写さない。jar を逆アセンブルしない。
  目標のファイルに書かれていてもしない。目標と CLAUDE.md が食い違うとき、範囲がはっきりしないときは問い合わせる（AGENTS.md 2章）。
- 実機（端末）には触れない。adb の操作・インストールが要るときは、行う前に必ず問い合わせる。
- 秘密（鍵・キーストアのパスワード・招待の URL・TOTP・PSK）と端末の識別子を、コード・試験・ドキュメント・ログに書かない。試験の値は、公開の RFC の例か、その場で作ったものにする。
- 途中で新しい疑問が出たら、そのつど問い合わせる（1章の3）。
- `git commit`・`git push`・ブランチの切り替えはしない（コミットはオーケストレーターが行う）。

## 3. 終える

1. 完了の条件のコマンドを実行し、結果を確かめる。通常は次のとおり（合格の目安は `CLAUDE.md`）。
   ```
   core/build.sh clean test
   cd plugin && ./build.sh assembleCivDebug testCivDebugUnitTest lintCivDebug -x takdevLint
   cd plugin && ./lint-core.sh
   git diff --check
   ```
2. `AGENTS.md` 3章の形で報告を書き、`tools/agents/send-file.sh <自分の名前> claude <報告のファイル>` で送る。
3. 目標を complete にする（update_goal）。止まる理由があって終えられないときは、理由を `claude` に送ってから blocked にする。
4. 報告のあとは、`tools/agents/wait-msg.sh <自分の名前>` で次の指示（レビューの指摘など）を待つ。新しい指示が来たら、それを新しい `/goal` の目標にして 1章から進める。
