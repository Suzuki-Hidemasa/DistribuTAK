# DistribuTAK の基本設計

DistribuTAK のプラグインの中の構成と、データの流れ、番地、本機・RadioLink との境目、試験の条件を書きます。機能は `02-functional-spec.md`、要件は `01-requirements.md` にあります。根拠は ADR 0030（`../decisions/0030-device-as-lan-router.md`）の答え 1〜107 です。

ADR 0030 で決まっていない点は「要確認」と書き、推測では埋めません。

## 1. 動く場所

| 場所 | 受け持つこと | 根拠 |
|---|---|---|
| EUD の ATAK の中のプラグイン | DistribuTAK のすべて（握手、仮想の網、証明書、DHT、CoT の同期、鍵の保管と消去） | 答え 2・11・36 |
| MPU-5 風機 | それ自身が EUD で、同じプラグインを動かす | 答え 9 |
| 本機 | ふつうの Wi-Fi ルーターとして通信を転送するだけ。DistribuTAK の鍵も証明書も持たない | 答え 3・36 |
| サーバー | 置かない（待ち合わせ・中継・STUN・TAK サーバーのどれも） | 答え 11・16・17 |

プラグインは自分の口を開いて待ち受けるので、プラグインが入っていない EUD には届かない（答え 11）。

## 2. プラグインの中の部品

この節の部品の分け方は、この基本設計で決めたものです。部品の名前は、この文書の中で呼ぶための名前で、コードの名前はまだ決めていません。

| 部品 | 受け持つこと | 主な機能（02） |
|---|---|---|
| 画面と設定 | グループを作る、管理者の操作、回線の優先度、QR コードを出す・読む、「消去」の操作 | DT-F1・F7・F8 |
| 鍵の保管 | 身元の鍵、握手の鍵、グループの鍵、管理者の鍵をしまい、消去で消す | DT-F4・F7 |
| グループの管理 | 証明書、失効の一覧、管理者の一覧に署名する・確かめる。新しいグループの鍵を HPKE で包む・開く | DT-F1・F4 |
| 相手を見つける | QR コードと URL を作る・読む、TOTP を確かめる、グループの DHT（Kademlia） | DT-F2 |
| つなぎ | UDP の口、回線ごとのソケット、IPv6 で直接つなぐ、NAT の穴あけ、回線の切り替え | DT-F3・F8 |
| 握手と仮想の網 | Noise の握手、相手ごとの鍵、時刻の値、仮想の網の番地 | DT-F3・F6 |
| CoT の同期 | ATAK と CoT をやり取りする、hide の扱い、`uid` と版、配り直し、食い違い、削除の印 | DT-F5 |

- ATAK から CoT を受け取る口と ATAK に CoT を渡す口は、ATAK のプラグインの SDK を使う。どの API を使うかは詳細設計で決める。SDK の例は写さない（引き継ぎ 6 章。DT-CN-06）。
- 鍵の保管の部品は、鍵を Android の Keystore の取り出せない AES の鍵で包み、プラグインの保存場所にしまう。Ed25519・X25519 を Keystore で持てない端末でも動くようにするため（答え 73）。消去では、この Keystore の鍵を消す。
- 暗号の部品は Bouncy Castle を使う。Noise と HPKE は、仕様どおりに組み、試験のベクトルで確かめる（答え 72）。

## 3. データの流れ

### 3.1 CoT を送る

1. CoT の同期の部品が、ATAK から CoT を受け取る。
2. hide の扱い（02 の 6.2）を確かめ、送ってよいものだけを選ぶ。
3. `uid` と版を付け、自分が送ったものとして覚える。
4. 握手が済んだ相手ごとに、握手と仮想の網の部品が暗号にする。
5. つなぎの部品が、優先度がいちばん高い回線の UDP の口から送る（答え 42・43・56）。

### 3.2 CoT を受ける

1. つなぎの部品が、UDP の口で受ける。
2. 握手と仮想の網の部品が、握手が済んだ相手からのものかを確かめ、復号する。握手の途中のものは握手として扱う（3.3）。
3. CoT の同期の部品が、`uid`・版・中身のハッシュを見る。3 つともが前に受けたものと同じなら、2 度目として捨てる（答え 42、ADR 0021 の決定 2）。
4. 食い違いは ADR 0021 の D1-4 で決める。同じ `uid`・版で中身が違うときは、中身のハッシュの小さい方を残す（答え 42、ADR 0021 の決定 2）。残ったものを ATAK に渡す。CoT の版は、その CoT を作った EUD の時刻と ID にする（答え 98）。
5. 4 で残すものが変わったとき（初めて受けたものを含む）だけ、配り直す。ホップ数が上限（仮に 16）より少なければ、受けた相手のほかの直接つながった相手に配る（答え 42・55）。

削除の印が消えたあとに届いた古い CoT のうち、stale の時刻を過ぎたものは、受けず、配り直さない（答え 86）。stale の時刻より前のものは受ける。このため、消したマーカーが stale の時刻まではまた出てくることがある（答え 94）。受ける EUD は、自分の時計より先すぎる版の時刻と、長すぎる stale の時刻に上限を付ける。上限を超えたものは断る。上限は、版の時刻が自分の時計の 5 分先まで、stale の時刻が自分の時計の 30 日先まで（答え 105・111・112・122）。

### 3.3 握手

1. つなぐ側は、URL・QR コード・グループの DHT から、相手の宛先と握手の鍵を得る（答え 17〜19）。
2. 1 通目に時刻の値と自分の証明書を入れて送る（答え 19）。
3. 受ける側は、時刻の値が相手ごとに前より新しいか、証明書が管理者の一覧に載った管理者の署名で、失効の一覧に無く、期限の中かを確かめる（答え 19・22・28・53）。期限は自分の EUD の時計で比べる（答え 85・98）。相手の握手の鍵が、証明書に入っている握手の鍵と同じかも確かめる（答え 84）。証明書に入っている、身元の鍵で握手の鍵に付けた署名も、管理者の署名と一緒に、証明書を受けるたびに確かめる（答え 97）。
4. 2 通目でグループの鍵（psk）が混ざり、握手が終わる（答え 21）。受ける側は、2 通目に自分の証明書を入れる。つなぐ側は、それを 3 と同じように確かめてから CoT などを送る（答え 102）。
5. 握手のときに、相手との時刻の差を測る（答え 46）。測った差は画面に出すだけにする（答え 85）。

相手が失効の一覧に載ったとき、新しい鍵に変わったとき、証明書の期限が切れたときは、その相手とのセッションをすぐに閉じる。グループの鍵を作り直したときは、残るメンバーと新しい鍵で握手し直す（答え 81）。閉じる理由の「新しい鍵」は証明書に入っている握手の鍵だけで、相手ごとに 2 分おきに作り直す鍵（答え 74）とグループの鍵の作り直しは入らない（答え 95）。

### 3.4 グループの管理の記録

1. 管理者の EUD のグループの管理の部品が、失効の一覧・管理者の一覧・包んだ新しいグループの鍵に署名する（答え 22・28・59）。メンバーの証明書は DHT に置かない。最初は管理者の EUD から直接受け取り（3.5。答え 60）、更新は管理者に届くときに行う（答え 24）。握手では 1 通目に自分の証明書を入れる（3.3。答え 19）。
2. 相手を見つける部品が、それらをグループの DHT に置く（答え 22・28・59）。
3. メンバーの EUD は、DHT から受け取り、管理者の一覧に載った管理者の署名を確かめてから使う（答え 28）。

### 3.5 入り直しの手順

新しいメンバー、新しいグループの鍵を受け取れなかったメンバー、証明書の期限が切れた EUD は、どれもこの手順でグループに入る（答え 60〜62）。

1. 管理者の EUD が、招待ごとに TOTP の秘密の値を乱数で作り、URL（または QR コード）に入れて渡す（答え 69）。
2. 入る側の EUD は、URL の宛先へ、管理者の EUD に直接つなぐ。グループの鍵もグループの DHT も使わない。
3. URL の TOTP の値で「入るためだけの握手」をする（答え 60）。
4. TOTP の値が正しければ、管理者の EUD が自動で（答え 149）、証明書とグループの鍵を、入る側の握手の鍵に向けて HPKE で包んで送る（答え 60・67）。
5. 入る側は、管理者の一覧に載った管理者の鍵の署名を確かめてから使う（答え 28・67・71）。管理者の一覧の署名は、URL に入った管理者の公開鍵で確かめる（答え 84）。その一覧から始め、一覧に載った管理者の署名を、版の順にいちばん新しい一覧までたどって（鎖で）確かめる（答え 96）。鎖に要る一覧は、招待した管理者の EUD が残し、入るためだけの握手の返事に入れて送る（答え 101）。最初の一覧は、URL を作った管理者がそのときの版の一覧に添えた署名で確かめる（答え 109）。

- 古いグループの鍵では、だれともつながらない。外した人も、同じ理由で外れたままになる（答え 61）。
- 招待の TOTP の秘密の値は、1 回入るのに使ったら消し、使われなければ 24 時間で消す。入り直しのたびに、管理者が新しい URL を作る（答え 82）。「1 回使った」は、入るためだけの握手の求めに管理者が証明書を出した時点（答え 93）。同じ返事を返すために、管理者の EUD は入る側の鍵・使った TOTP の値・出した返事を、その時間のあいだだけ残す（答え 106）。
- 手で消去したとき、自分の失効を受けて消去したときは、利用者が新しい招待の URL か QR コードを読むまで、入るためだけの握手を始めず、待ち受けもしない（答え 103・104）。
- 「入るためだけの握手」のメッセージは Protocol Buffers で並べる（答え 88）。項目はまだ決めていない（`04-detailed-design.md` の 9 章）。

## 4. 番地

| 網 | 番地 | 根拠 |
|---|---|---|
| DistribuTAK の仮想の網 | 端末の ID から作る IPv6 のユニークローカルアドレス（`fd00::/8`）。割り当てる役は置かない | 答え 58 |
| 本機の HaLow のメッシュ | 1 つのサブネット（ADR 0022 決定 9） | 答え 44 |
| MPU-5 風機の LAN | 本機と USB でつなぎ、別のサブネットにする | 答え 44 |
| 本機の LAN の IPv6 | ULA と、上流から受けたプレフィックスを配る | 答え 44 |
| 本機の LAN のサブネット | グループごとに、本機の設定で決める | 答え 44 |

DistribuTAK は仮想の網の番地で相手を区別するので、Wi-Fi の LAN の番地が重なっても響かない（答え 44）。

- 端末の ID は、身元の鍵（Ed25519）の公開鍵の BLAKE2s-256 にする。ULA は `fd` のあとに端末の ID の先頭の 120 ビットを並べたものにする（答え 70。`04-detailed-design.md`）。

## 5. 本機・MPU-5 風機・RadioLink との境目

| 相手 | 境目 | 根拠 |
|---|---|---|
| 本機の Wi-Fi | EUD は本機に Wi-Fi の LAN の 1 つとしてつなぐ。プラグインは本機の名前を出さない | 答え 3・7・10 |
| 本機の WAN | インターネット向けの通信は、本機の有線の WAN の口から出す。HaLow では運ばない。口は USB（答え 118）。usb0 との分け方は未決（本機の側の話） | 答え 1・35・118 |
| 本機と MPU-5 風機の LAN の間 | IP をすべて経路で転送する。電波へ出るところは、それぞれの機器の許可リストと送信ゲートで止める | 答え 5・37 |
| 本機の `datad` | D6 はサーバーの役を持たない。D6 の窓口はなくす（ADR 0023 の U-PL-1 (a) はこれで変わる） | 答え 8 |
| ADR 0028 の電話の中の CA | 使わない。DistribuTAK のグループの証明書と分ける | 答え 45 |
| RadioLink | 本機の操作（ext-link）と、本機の無線で送る CoT のうち IP を通さない経路の分を受け持つ別のプラグイン。DistribuTAK は ext-link を使わない | 答え 10・39・40 |
| SCU | DistribuTAK からは触れない。本機の送信を許したり止めたりする口は作らない。SCU のゼロ化は DistribuTAK に届かない | 答え 11・40・46 |

- 答え 35〜37（本機の WAN の口、LAN の間の転送）は、legal Q107 (3) の確認が済んでから行う（(2) は無償に限っての答えを得た。答え 161）。(3) は利用者が問い合わせ中で、まだ判断していない。
- 本機の HaLow のブリッジは、legal Q99 (4)(5) を確かめるまで有効にしない（ADR 0030「変えないこと」）。

## 6. 試験の条件

答え 47 の仮の値です。あとで直せます。

| 項目 | 仮の値 |
|---|---|
| EUD の数 | 2・5・10 台 |
| SA の間隔 | ATAK の既定 |
| 回線 | LAN とモバイル回線 |
| 測るもの | 1 時間のデータ量と電池の減り |
| 本機の経路の音声の優先と送信時間 | 今の `../detailed-design/06-apu-software.md` 10.5 の数え方のまま |
| ホップ数の上限 | 16（答え 55。仮の値） |

- 65536 台のグループで動くこと（答え 48・57。DT-NF-02）は、模擬の試験で確かめる。PC の上でプラグインの DHT と同期の部品をたくさん動かし、負荷と届くまでの時間を測る。実機の試験は数台で行う（答え 91）。
