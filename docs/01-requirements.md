# DistribuTAK の要件

DistribuTAK（ATAK のプラグイン）の要件です。根拠は ADR 0030（`PRC-163:docs/decisions/0030-device-as-lan-router.md`）の答え 1〜107 です。番号の引き方は `README.md` の 2 章のとおりで、「答え N」は ADR 0030 の「未決への利用者の答え」の N 番を指します。

要件の ID は `DT-` で始めます。本機（PRC-163 風機）の要件（`PRC-163:docs/requirements.md`）とは別に立てます。

## 1. 目的と範囲

### 1.1 目的

同じグループの EUD（Android の端末）どうしが、LAN・WAN・モバイル回線の上で CoT を同期できるようにします。各 EUD が、分散型の TAK サーバーの役を持ちます（答え 2）。本機が無くても動きます（網の見方 4）。

### 1.2 範囲に入れないもの

- 本機の操作（ext-link）と、本機の無線で送る CoT のうち IP を通さない経路の分（LoRa など）。これは別のプラグイン RadioLink が受け持ちます（答え 10・39・40）。
- ATAK の標準の TAK サーバーの接続（答え 11）。
- 端末全体の VPN（Android の VpnService。答え 15）。

## 2. 用語

| 用語 | 意味 |
|---|---|
| EUD | ATAK を入れた Android の端末。MPU-5 風機も、それ自身が EUD になる（答え 9） |
| グループ | DistribuTAK で CoT を同期する EUD の集まり。グループの鍵と、管理者が署名した証明書で区切る。本機の鍵グループ（ADR 0024）とは別のもので、プラグインの中だけにある（答え 2・21・22・63） |
| 管理者 | グループの証明書・失効の一覧・管理者の一覧に署名する EUD。署名には、管理者ごとに身元の鍵とは別の Ed25519 の鍵（管理者の鍵）を使う（答え 22・25〜28・71） |
| 身元の鍵 | 端末ごとの Ed25519 の鍵。公開鍵の BLAKE2s-256 が端末の ID になる（答え 14・20・46・70） |
| 握手の鍵 | 端末ごとの X25519 の鍵。身元の鍵で署名する（答え 20） |
| 仮想の網 | プラグインの中だけの網。プラグインの通信だけが使う（答え 12・15） |
| 回線 | Wi-Fi の LAN、モバイル回線など、Android が持つ網（Network）。本機は Wi-Fi の LAN の 1 つとして見える（答え 3・7・10） |

## 3. 機能の要件

### 3.1 同期

| ID | 要件 | 根拠 |
|---|---|---|
| DT-FN-01 | 同じグループの EUD どうしで CoT を同期する | 答え 2 |
| DT-FN-02 | プラグインは自分の口を開き、ほかの EUD に入った同じプラグインからの接続を待ち受ける。同じ口でほかの EUD へもつなぐ | 答え 11 |
| DT-FN-03 | 同じプラグインが入っていない EUD には届かない。グループの鍵を持たない EUD は中身を復号できない | 答え 11・21 |
| DT-FN-04 | hide の印のものは、グループの中だけに通す。hide を守れない経路は使わない。印は `<__share scope="group"/>` にし、古い印 `<__prc163 share="1"/>` は読まない | 答え 4・64・68（ADR 0025） |
| DT-FN-05 | 直接つながった相手から受けた CoT を、ほかの直接つながった相手に配り直す。`uid`・版・中身のハッシュがどれも同じものを 2 度目として捨て、ホップ数に上限を付ける | 答え 42・52・55、ADR 0021 の決定 2 |
| DT-FN-06 | 食い違いは、ADR 0021 の D1-4（後勝ち・版）で決める。同じ `uid`・版で中身が違うときは、中身のハッシュの小さい方を残す | 答え 42・98、ADR 0021 の決定 2 |
| DT-FN-07 | 削除は、版つきの削除の印を配って行う。印は 30 日残してから消す | 答え 46・54 |

### 3.2 つなぎ方

| ID | 要件 | 根拠 |
|---|---|---|
| DT-FN-10 | CGNAT を越えてつながる | 答え 6 |
| DT-FN-11 | 越え方は、プラグインの中のオーバーレイの VPN（仮想の網）にする | 答え 12・15 |
| DT-FN-12 | つなぐ順は、IPv6 で直接 → NAT の穴あけ（ポートの予測を含む）。どちらでもつながらなければ、つながらないことを画面に出す | 答え 16 |
| DT-FN-13 | 中継（サーバー・ほかの EUD）は置かない。外の STUN サーバーは使わない。自分が外からどう見えているかは、相手から教えてもらう | 答え 16・52 |
| DT-FN-14 | 相手を見つける方法は、QR コード、ワンタイムパスワード付きの URL、グループの中だけの DHT の 3 つにする | 答え 13・17・18 |
| DT-FN-15 | 待ち合わせのサーバーは置かない。公開の DHT には加わらない | 答え 17・18・57 |
| DT-FN-16 | 使う回線は、利用者がプラグインで優先度を選ぶ。優先度がいちばん高い回線 1 本で送り、切れたら次の回線に切り替える | 答え 7・42 |
| DT-FN-17 | 回線は通信ごとに指定し、ATAK のほかの通信に影響を与えない。インターネットにつながらない Wi-Fi の LAN でも使える | 答え 43 |

### 3.3 グループと管理者

| ID | 要件 | 根拠 |
|---|---|---|
| DT-FN-20 | 最初の管理者は、グループを作った人にする | 答え 25 |
| DT-FN-21 | 管理者は、メンバーからのリクエストを管理者の 1 人が認めるか、管理者が与えることで増やせる | 答え 25・26 |
| DT-FN-22 | どの管理者も、ほかの管理者（グループを作った人を含む）の権限を外せる。管理者が 1 人もいなくなる操作はできない | 答え 27 |
| DT-FN-23 | だれが管理者かは、管理者が署名した管理者の一覧で、グループの DHT を通して知らせる | 答え 28 |
| DT-FN-24 | メンバーを外すときは、失効の一覧に載せ、グループの鍵を作り直して、残る人に配る | 答え 21・22・59 |
| DT-FN-25 | 1 つのグループのメンバーになれる EUD は、通常で 256 台まで、オプションで 65536 台まで | 答え 48 |
| DT-FN-26 | 新しく入るメンバーは、TOTP の URL（または QR コード）で管理者の EUD へ直接つなぎ、最初の証明書とグループの鍵を受け取る（入り直しの手順） | 答え 60 |
| DT-FN-27 | 新しいグループの鍵を受け取れなかったメンバーと、証明書の期限が切れた EUD は、入り直しの手順を使う | 答え 61・62 |
| DT-FN-28 | 管理者が署名して DHT で配る記録には版の番号を付け、知っている中でいちばん新しい版より小さい版を捨てる | 答え 75 |

### 3.4 鍵の写しと消去

| ID | 要件 | 根拠 |
|---|---|---|
| DT-FN-30 | 管理者の鍵の写しは、管理者がはっきり操作したときだけ、QR コードで取り出す。パスフレーズでは包まない | 答え 30・31 |
| DT-FN-31 | 写しから戻すときは、別の端末の画面に出した QR コードを、プラグインのカメラで読み取る。画像のファイルから読み込む口は持たない | 答え 34 |
| DT-FN-32 | プラグインは 1Password と連携しない。1Password への保存は利用者が手で行う | 答え 32 |
| DT-FN-33 | プラグインの「消去」の操作と、自分の失効を受けたときに、鍵とデータを消す。どちらのときも、先にすべてのセッションを閉じ、つなぎ直しと待ち受けを止める。消したあとは、利用者が新しい招待の URL か QR コードを読むか、新しいグループを作るまで、どこにもつながない。消したあとに作るグループは、元のグループとは別のグループにする（ID・鍵をすべて新しく作る） | 答え 46・99・103・104・164 |
| DT-FN-34 | 鍵は、Android の Keystore の取り出せない鍵で包んでから、プラグインの保存場所にしまう | 答え 73 |
| DT-FN-35 | （後の段）1 台の EUD が複数のグループに同時に入れるようにする。異なるグループの間では自分のデータだけを送り、あるグループから受けたほかのメンバーのデータ（CoT・DHT の記録・ファイルなど）を別のグループに送らない。自分のデータは、自分の位置と自分の ATAK で作った物だけ。他人のデータは手で選んでも送らない。位置を送るかはグループごとに設定し、作った物は送るグループを選ぶ（既定は、いま選んでいるグループだけ）。鍵・端末の ID・ポート・保存・DHT はグループごとに分け、別のグループからは同じ端末だと分からないようにする | 答え 164 (5)・165 |

## 4. 安全の要件

| ID | 要件 | 根拠 |
|---|---|---|
| DT-SC-01 | 相手は Noise の握手（IKpsk2）で確かめる。身元の鍵は Ed25519 | 答え 14・19 |
| DT-SC-02 | 身元の鍵と握手の鍵を分けて作る。握手の鍵は身元の鍵で署名する | 答え 20 |
| DT-SC-03 | グループの鍵は、握手に psk として混ぜる | 答え 21 |
| DT-SC-04 | 握手の 1 通目には、時刻の値と証明書のほかは入れない。相手ごとに、受けた中でいちばん新しい時刻の値を覚え、それ以下の時刻の 1 通目を捨てる | 答え 19・53 |
| DT-SC-05 | 1 通目の中の証明書を確かめて、グループの外の EUD を弾く。握手を始めた側も、2 通目の中の証明書を同じように確かめてから CoT などを送る | 答え 21・22・102 |
| DT-SC-06 | 証明書は管理者が署名し、期限は 30 日。残りが 3 分の 1 ほどになったら、管理者に届くときに自動で更新する | 答え 22・24 |
| DT-SC-07 | 失効の一覧は管理者が署名し、グループの DHT で配る | 答え 22 |
| DT-SC-08 | ワンタイムパスワードは TOTP にする。1 度正しく使えた値は、時間の枠の中でも 2 度目を受けない。同じ求め（同じ鍵・同じ値）の送り直しに前の返事をもう一度返すのは、2 度目に受けることに入らない | 答え 17・23・53・93 |
| DT-SC-09 | DistribuTAK のグループの証明書は、ADR 0028 の電話の中の CA と分ける | 答え 45 |
| DT-SC-10 | 握手が済んだあとの相手ごとの鍵は、WireGuard の値で作り直す | 答え 74 |

## 5. 性能と試験の要件

## 6. 制約

| ID | 制約 | 根拠 |

| DT-CN-04 | プラグインの名前・画面・設定・パッケージ名に、本機の名前と商標を出さない | 答え 7・10・50 |

| DT-CN-06 | ATAK の SDK・ATAK-CIV のコードをリポジトリに入れない。SDK の例を写さない。SDK・takdev の jar を逆アセンブルしない。署名の検査を迂回する方法を調べない・作らない。例のキーストアの合言葉を文書に書かない | 引き継ぎ 6 章 |
| DT-CN-07 | 送る・上げる・フォームに入れる前には利用者に確かめる。tak.gov へは利用者が自分で上げる。TPP（tak.gov/user_builds）は使えることを確認済み。TPC（TAK Product Center）の認証は将来の作業（2026-11-16 の利用者の決定） | 引き継ぎ 6 章 |
| DT-CN-08 | 他人の CoT の配り直しと、他人の記録を預かる DHT は、legal Q107 (2) で無償で提供する場合に限り事業に当たらず届出も要らないとの口頭の答えを得た（2026-11-12。ADR 0030 答え 161。料金を取るなど条件が変わるときは聞き直す）。本機の HaLow を通る分の電波法 59 条（Q102 (6)）と携帯回線の約款（Q107 (3)）は、確認を待っている。暗号の輸出と TPP の出し直しは legal Q100 (b)・Q107 (6) で確かめる。どれも、まだ判断していない | 答え 11・18・52・59・161 |

## 7. 要確認

要件の段階の要確認は、答え 63（グループは本機の鍵グループと別）と答え 64・68（hide の印の名前）で決まりました。パッケージ名の具体の名前（DT-CN-05）は、答え 76 で決まりました。機能・設計の段階の要確認は、`README.md` の 6.1 にまとめています。
