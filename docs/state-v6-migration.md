# 保存形式6への移行

版2〜5の保存は消去せず読み込みます。読み込みだけではstateの形式を変えず、通常通信を開く前に停止印の固定領域を確保します。次の保存成功で版6へ進みます。身元・握手・管理者・グループの各鍵、証明書、保存相手、更新待ち、保存と発見の番号、同期の初期化状態を保ちます。同期の記録と外来の印も引き継ぎます。

版6を一度保存した端末では、版5までの旧APKへ戻さないでください。旧APKは版6と管理ファイルを読めません。形式2の管理ファイルを書いたあとは、stateの版が6でも第7回のAPKへ戻すと読めません。互換性のために保存を消したり、グループを作り直したりする手順は設けません。

更新後は通常の起動と保存で移行します。「保存がいっぱい」で止まった場合は記録を消さず、空きを作って起動し直します。第8a回は、検証できた停止印の要件があるとき、保存相手と既存の接続候補から失効一覧を取り直す限定復旧を行います。全ゼロの「候補なし」も対象です。取り直した署名済み一覧が必要な版以上で、保存済みの失効の和を包含し、履歴を削らず保存できることが必要です。新checkpointには元の停止要件と包含の証拠を残し、保存とclearの同期後に現在の権限・失効・期限を検査して通常通信へ戻ります。

**第7回のAPKは実機へ入れないでください。第8a回は限定復旧まで、第8b-1回は通常の失効ページの受信・保存・完了ACKまでの区切りです。** 第7回には全ゼロの停止を解く経路がありません。限定復旧は既存候補を一巡だけ試し、相手が30秒を過ぎて応答しても、試した相手は次の起動まで試しません。返答できる相手も、形式2の署名済み一覧を持つ8a以降に限ります。第8a回でも、履歴65,536件・12 MiBまたは管理平文16 MiBの仮の上限を越える場合は、履歴を削らず停止を保ちます。鍵の入れ替えで全相手が旧鍵の握手を断る場合、鍵不一致、証明書期限切れ、管理者鎖の欠け、包含の証拠不足、相手なし・応答なし・保存失敗でも復旧できません。再起動だけで直るとは保証しません。旧鍵・旧PSK・平文の取得口や証明書検査の緩和で回避せず、自動消去やグループの作り直しも行いません。印や管理ファイルが壊れた場合は、古い世代を探して自動復元しません。

第8b-1回では、通常通信中の失効ページも検証して保存し、clear同期後に現在のセッション・世代・権限・期限を検査してから完了ACKを返します。勝者にならなくても失効の和が増えて履歴と和に保存した一覧は、保存したものとしてACKできます。保存しなかった一覧は、保存済みの現行一覧と版・署名を含む内容が正確に一致する場合だけ、再保存せずACKできます。別の操作番号でも全体を再検証して一致を調べ、成功確定の記録を使い回しません。和を増やさない非勝者で保存済みと一致しない一覧には完了ACKを返しません。限定復旧では、停止時の要件と保存済みの和を包含しない一覧も断ります。保存に失敗したら通信と保留を止め、再起動で停止印を検証します。

通常時の保存中は、認証済みの既存セッションで届く失効ページだけを相手80件・全体256件・1 MiBの共通枠に預けます。受信から30秒以上の保留は処理の対象から外れますが、保存中は `SyncInbox` から取り出さず、その時点では平文を消しません。保存が終わって最初に取り出すときに期限を検査し、期限切れの平文をゼロ埋めして捨てます。close・STORAGE_FAILEDでも消去し、保持量は共通枠の上限内です。既存組立の初回から240秒以上の入力も捨て、保存時間で期限を延ばしません。組立が済んだ対象の完了ACKの時点では初回ページから240秒を検査し、未完組立の進捗30秒は当てません。復号して捨てた入力は同じ暗号文では受け直せないため、送り手の新しい送信と後段の探索で補います。通常時に復旧要求10は送りません。

完了ACKを失った同じ送信には、保存成功を確定したメモリ上の記録（共通8件・初回ページから240秒）の範囲でACKだけを返し、再保存しません。復旧成功時にも記録を残しますが、セッション終了・押し出し・期限切れ・再起動で消えた成功は推測しません。保存形式と限定復旧の一巡・240秒・30秒・要求再送の条件は変えません。

実機の2台は版5の保存を持ちます。新旧のビルドが混ざると同じ鍵版の入り直しが断られるため、更新は2台そろえて行います。第8b-1回でも、名簿・初回proof2・告知・包み・探索・新鍵と通常操作全体の調整層への配線は8b-2以降に残ります。

この文書は実機操作やAPK配布を指示するものではありません。8aや8b-1のマージは、実機の更新の承認ではありません。実機の更新は利用者とオーケストレーターが決め、行います。
