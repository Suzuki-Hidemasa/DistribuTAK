# 保存形式6への移行

版2〜5の保存は消去せず読み込みます。読み込みだけではstateの形式を変えず、通常通信を開く前に停止印の固定領域を確保します。次の保存成功で版6へ進みます。身元・握手・管理者・グループの各鍵、証明書、保存相手、更新待ち、保存と発見の番号、同期の初期化状態を保ちます。同期の記録と外来の印も引き継ぎます。

版6を一度保存した端末では、版5までの旧APKへ戻さないでください。旧APKは版6と管理ファイルを読めません。形式2の管理ファイルを書いたあとは、stateの版が6でも第7回のAPKへ戻すと読めません。互換性のために保存を消したり、グループを作り直したりする手順は設けません。

更新後は通常の起動と保存で移行します。「保存がいっぱい」で止まった場合は記録を消さず、空きを作って起動し直します。第8a回は、検証できた停止印の要件があるとき、保存相手と既存の接続候補から失効一覧を取り直す限定復旧を行います。全ゼロの「候補なし」も対象です。取り直した署名済み一覧が必要な版以上で、保存済みの失効の和を包含し、履歴を削らず保存できることが必要です。新checkpointには元の停止要件と包含の証拠を残し、保存とclearの同期後に現在の権限・失効・期限を検査して通常通信へ戻ります。

**第7回のAPKは実機へ入れないでください。第8a回は限定復旧を持ちますが、通常の失効の受信は第8b回まで動きません。** 第7回には全ゼロの停止を解く経路がありません。限定復旧は既存候補を一巡だけ試し、相手が30秒を過ぎて応答しても、試した相手は次の起動まで試しません。返答できる相手も、形式2の署名済み一覧を持つ8a以降に限ります。第8a回でも、履歴65,536件・12 MiBまたは管理平文16 MiBの仮の上限を越える場合は、履歴を削らず停止を保ちます。鍵の入れ替えで全相手が旧鍵の握手を断る場合、鍵不一致、証明書期限切れ、管理者鎖の欠け、包含の証拠不足、相手なし・応答なし・保存失敗でも復旧できません。再起動だけで直るとは保証しません。旧鍵・旧PSK・平文の取得口や証明書検査の緩和で回避せず、自動消去やグループの作り直しも行いません。印や管理ファイルが壊れた場合は、古い世代を探して自動復元しません。

実機の2台は版5の保存を持ちます。新旧のビルドが混ざると同じ鍵版の入り直しが断られるため、更新は2台そろえて行います。第8a回は限定復旧までの区切りで、名簿・初回proof2・通知・探索・新鍵の通常通信への配線は第8b回に残ります。

この文書は実機操作やAPK配布を指示するものではありません。8aのマージは、実機の更新の承認ではありません。実機の更新は利用者とオーケストレーターが決め、行います。
